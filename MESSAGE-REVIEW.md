# Website messages and AI coverage review

Reviewed 19 November 2026. This is a source and trigger review, with focused chat/EarlyGrad tests. It is not a claim that every student-history combination has been exercised in a browser. Findings below are proposals for discussion; the website's existing information/caution/error messages have not been changed by this review.

## AI change completed first

- Shared chat instructions now ask for the early-completion invitation in the first relevant subject-planning/completion response. The invitation is not repeated, does not replace the answer, and is skipped in favour of actually answering an early-completion question already asked.
- Follow-up instructions explicitly cover the same individual circumstances as EarlyGrad: baseline, completions and credits, complete conditional sequences, major alternatives, prerequisites, Capstone, one eligible final-year overload, BIT Summer, once-only BET207, available USE slots, multiple Summers, final-Summer completion, uncertainty and the conditional other-provider note.
- The website chat receives compact calculated baseline/examples in its main-planner context. The localhost MCP connection now retains these fields instead of dropping them in its academic-data filter.
- Hypothetical subjects are explicitly separated from actual passed/credited/current subjects. Existing USE credits with unidentified sources do not prove whether BET207 was used. Corrected history invalidates earlier examples.
- This changes the source. No production deployment or live-model conversation was performed. Mocked chat tests establish instruction routing, not guaranteed model compliance.

Sources: `planner-instructions.mjs`, `script.js` (`getEarlyGradChatContext`, `getAcademicPlannerContext`, `seedFriendlyChatFromPlanner`), `tools/local-planner-server.mjs` (`academicOnly`).

## What to discuss before expanding AI message coverage

1. **Agree on the rule corrections first:** next-semester eligibility count, duplicate-credit title, median versus average, census/last-add distinction, and the repeat-failure policy wording.
2. **Share structured decisions, not rendered messages:** a stable message/rule ID, severity, confirmed/provisional status, relevant subject codes, evidence date and safe next action. The present localhost alert text is capped and can truncate long notices; the new structured EarlyGrad evidence solves this particular case, not the entire alert catalogue.
3. **Preserve staff/student boundaries:** public chat gets only information the student supplied or is authorised to see. Imported holds, CoE checks, nationality/support flags and staff notes must not be copied indiscriminately.
4. **Match urgency to context:** answer a student's actual question, include applicable blockers, offer a next step and useful alternatives. Do not repeat the complete alert catalogue in every reply. The localhost connection currently requests all current alert summaries on its first response for a new student; that instruction deserves review against this goal.
5. **Keep one source of course truth:** website calculations, ordinary eligibility tools and conditional acceleration exceptions should share explicit assumptions. Prompt instructions cannot replace a missing calculation or authoritative individual decision.
